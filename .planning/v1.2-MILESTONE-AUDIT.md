# v1.2 Trailer Video YouTube Publishing — Milestone Audit

## Scope

This audit covers the implemented v1.2 work in Phases 7, 8, 8.1, and 9, plus the deferred Phase 10 and 11 requirements recorded in `ROADMAP.md` and `REQUIREMENTS.md`.

The current implementation is not ready for milestone completion. The core trailer upload → private YouTube transfer → title/hashtag/summary commit → publication flow is wired, but the existing artifact-download workflow is incomplete.

### Unsatisfied requirements

- `ARTIFACT-01`: the Episodes download modal cannot offer the finalized trailer video because `EpisodeArtifactSelector` and `artifactDefinitions` omit `trailer-video`.
- `ARTIFACT-02`: the UI cannot send `trailer-video` in an artifact request, so the generated ZIP cannot contain `trailer.mp4` through this client. The sibling API's canonical artifact and preflight behavior are already implemented and verified.
- `OPS-05`: compatibility is not complete because restored editors do not resume pending summary polling and Save clears the editor before asynchronous YouTube commit completion is surfaced. The missing artifact flow is not part of OPS-05 and remains the separate Phase 11 ARTIFACT-01/02 scope.

## Cross-phase integration

### Integrated flow

The primary flow is connected end to end:

1. Angular reserves a new-episode trailer draft.
2. The MP4 is uploaded with progress and the draft identity.
3. The API stages the file and starts or reuses a private YouTube job.
4. Angular polls the sanitized job snapshot and displays transfer, processing, and private-ready states.
5. Summary polling and hashtag authoring feed the computed title and publication metadata.
6. Save creates/promotes the episode and requests API-owned YouTube commit/publication.
7. The API applies title, summary, and hashtags, publishes after private readiness, and stores the YouTube link.

Existing trailer replacement is wired in the current source through the persisted replacement path and API rollback-safe cleanup. The Phase 7 verification report predates that correction and should not be treated as current proof; browser recovery evidence is still absent.

### Broken or risky links

- **Artifact boundary:** API catalog → Angular artifact selector is broken. This is the release blocker.
- **Summary recovery:** `startEdit()` restores summary data but does not restart polling for an already-pending summary after reload.
- **Save feedback:** `saveEpisode()` starts the asynchronous commit and immediately resets/reloads the editor. The API operation remains valid, but late commit failures are reported after the form is gone.
- **Runtime verification:** source-level guards cover episode, filename, draft, job, and generation identity, but the audit did not execute a live browser flow for reload, retry, cancellation, replacement, or provider failures.
- **Auth configuration:** frontend `authBypass` and API `AUTH_BYPASS` must be configured consistently; enabling only the frontend bypass does not authorize API requests.

The API's direct `/youtube-trailer-jobs/:jobId/publish` route has no Angular caller. This is not a functional break because the documented and tested Save-time `/commit` route owns publication, but it is an unused API surface.
