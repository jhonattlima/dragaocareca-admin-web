# Codebase Structure

**Analysis Date:** 2026-07-24

## Directory Layout

```text
dragaocareca-admin-web/
├── angular.json              # Angular CLI project configuration
├── package.json              # Scripts, deps, and build/test entry points
├── package-lock.json         # npm lockfile
├── docs/                     # Project documentation
│   └── SDD.md                # Source of truth for UI/backend contract assumptions
├── scripts/                  # Small Node helper scripts
│   └── capture-metrics-screenshot.js
├── src/                      # Angular application source
│   ├── app/                  # Components, pages, and core services
│   ├── assets/               # Static assets
│   ├── environments/         # Environment toggles and API config
```

## Directory Purposes

**src/app/**
- Purpose: Angular application code.
- Contains: feature pages, shell components, auth/API services.
- Key files: `app.module.ts`, `app-routing.module.ts`, `core/api.service.ts`, `core/auth.service.ts`.
- Subdirectories:
  - `core/` - Shared services, guard, interceptor.
  - `pages/` - Routed screens and page-specific components.

**src/app/pages/**
- Purpose: User-facing admin screens.
- Contains: `login`, `dashboard`, `manage`, `feed`, `metrics`, `health`, `masthead`.
- Key files: `manage/manage.component.ts`, `feed/feed.component.ts`, `metrics/metrics.component.ts`.
- Subdirectories: Each screen keeps its own `.ts`, `.html`, and `.scss` files.

**src/environments/**
- Purpose: Environment-specific config.
- Contains: `environment.ts`, `environment.prod.ts`.
- Key files: `authBypass`, `apiBaseUrl`, `googleClientId`.
- Subdirectories: None.

**docs/**
- Purpose: Canonical human documentation.
- Contains: SDD and related design notes.
- Key files: `SDD.md`.
- Subdirectories: None in the inspected tree.

**scripts/**
- Purpose: Maintenance and capture helpers.
- Contains: Node scripts.
- Key files: `capture-metrics-screenshot.js`.
- Subdirectories: None.

**.planning/**
- Purpose: Workflow state and generated project documents.
- Contains: `codebase/`, onboarding summary, and future project planning docs.
- Key files: `.planning/codebase/*.md`, `.planning/onboarding/SUMMARY.md`.
- Subdirectories: generated by GSD workflows.

## Key File Locations

**Entry Points:**
- `src/main.ts` - Angular bootstrap.
- `src/app/app.module.ts` - Root module declarations and providers.
- `src/app/app-routing.module.ts` - Route table and auth guard wiring.

**Configuration:**
- `angular.json` - Build/serve/test targets and budgets.
- `tsconfig.json` - TypeScript strictness and target.
- `src/environments/environment.ts` - Local auth/API config.
- `src/environments/environment.prod.ts` - Production auth/API config.

**Core Logic:**
- `src/app/core/api.service.ts` - HTTP orchestration and shared response types.
- `src/app/core/auth.service.ts` - Login, local token storage, bypass checks.
- `src/app/core/auth.guard.ts` - Route gating.
- `src/app/core/auth.interceptor.ts` - Authorization header injection.
- `src/app/pages/manage/manage.component.ts` - Primary admin workflow implementation.

**Testing:**
- `src/app/app.component.spec.ts` - Currently stale unit spec.
- `src/**/*.spec.ts` - Angular default unit-test location, but little coverage exists.

**Documentation:**
- `docs/SDD.md` - Canonical product and backend-contract note.
- `README.md` - Basic run/build instructions.
- `AGENTS.md` - Local repo rules for future agents.

## Naming Conventions

**Files:**
- kebab-case for Angular files and feature directories.
- `.component.ts/.html/.scss` triplets for UI components.
- `.spec.ts` for tests, colocated with source.

**Directories:**
- Lowercase, feature-oriented directories (`core`, `pages`, `manage`).
- `pages/` holds routed screens; `core/` holds shared app infrastructure.

**Special Patterns:**
- `environment*.ts` for environment-specific values.
- `*.component.*` for Angular component triplets.
- `app-routing.module.ts` and `app.module.ts` for root wiring.

## Where to Add New Code

**New Feature:**
- Primary code: `src/app/pages/<feature>/`
- Shared support: `src/app/core/`
- Config if needed: `src/environments/`

**New Component/Module:**
- Implementation: `src/app/pages/<feature>/` or `src/app/core/`
- Types: same feature directory or `src/app/core/api.service.ts` if shared
- Tests: colocated `*.spec.ts`

**New Route/Command:**
- Definition: `src/app/app-routing.module.ts`
- Handler: `src/app/pages/<feature>/`
- Tests: colocated spec files for the routed component

**Utilities:**
- Shared helpers: `src/app/core/` unless they are page-specific.
- Type definitions: `src/app/core/api.service.ts` currently owns most shared response types.

## Special Directories

**src/assets/**
- Purpose: Static assets compiled into the app bundle.
- Source: Checked-in files, plus backend-provided asset manifest references.
- Committed: Yes.

**.planning/codebase/**
- Purpose: Generated codebase map for GSD onboarding/planning.
- Source: Workflow-generated documentation.
- Committed: Intended for workflow use; repo policy decides tracking.
