# Phase 8.1: Episode Form Stability Patch - Context

**Gathered:** 2026-08-14
**Status:** Ready for planning

<domain>
## Phase Boundary

Harden the Add Episode form so episode publication defaults, uploaded-audio metadata, participant/music validation, and read-only field presentation are reliable. The patch covers only the episode audio metadata path; trailer-audio behavior remains unchanged. Frontend orchestration should consume backend-confirmed metadata and keep business rules in the API where appropriate.

</domain>

<decisions>
## Implementation Decisions

### Publication date defaults
- **D-01:** When a previous episode exists, auto-fill the new episode publication date as seven calendar days after the latest episode’s date/time, preserving its local time and timezone representation.
- **D-02:** When no previous episode exists, default the publication date to the current date/time.
- **D-03:** “Latest episode” is determined from the existing episode publication-date ordering used by the Add Episode workflow.

### Episode audio metadata
- **D-04:** Extract and populate metadata only for the episode audio upload, not trailer audio.
- **D-05:** Populate Duration and Bytes only after upload completion, using values confirmed by the backend.
- **D-06:** Display duration as `HH:MM:SS`.
- **D-07:** Display bytes as decimal megabytes (`1 MB = 1,000,000 bytes`).
- **D-08:** If required duration or byte metadata cannot be extracted/confirmed, the upload must fail rather than leave a required field blank.

### Participants and music validation
- **D-09:** Default participants are configured in frontend environment/configuration so an administrator can change the list without changing component logic.
- **D-10:** Apply configured participant defaults only when the configured participant exists in the current participant catalog; unknown configured names are ignored.
- **D-11:** Saving an episode requires at least one music credit with both a non-empty music name and a non-empty reference link. The Save button may remain disabled until this requirement is met.

### Read-only presentation
- **D-12:** Duration, Bytes, and Spotify ID are not user-editable.
- **D-13:** Their read-only state is communicated through light-gray field styling only; no helper or hint text is required.

### the agent's Discretion
- The assistant may choose the exact decimal-MB rounding/formatting presentation, audio metadata extraction implementation, environment configuration key names, and API/UI error wording, provided the locked behavior above is preserved.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- Existing episode-audio upload progress and cancellation flow should be reused for metadata completion/error handling.
- Existing latest-episode lookup and `suggestedNextPubDate` state can be corrected rather than replaced.
- Existing participant catalog and music-credit form arrays provide the established data-binding patterns.

### Established Patterns
- The Manage page uses a sectioned, legacy-inspired form and keeps API calls in the component/API service boundary.
- Episode save eligibility is centralized in `isEpisodeSaveDisabled`; the music-credit rule belongs in that gate and should also be reflected in validation feedback.
- Existing read-only inputs use native `readonly` behavior; this phase adds visual styling without introducing explanatory hints.

### Integration Points
- The episode audio upload response must expose or map backend-confirmed duration and bytes into the form model after successful completion.
- Environment configuration must provide the default participant list while preserving existing `authBypass` behavior.
- The sibling API may need a focused upload-response or metadata-validation adjustment if it does not currently return confirmed duration and bytes.

</code_context>

<specifics>
## Specific Ideas

- The participant defaults should be editable from configuration and should not silently select names that are absent from the current participant catalog.
- The publication date should preserve the latest episode’s time, not normalize to midnight.
- The user explicitly prefers visual read-only styling without additional hint text.

</specifics>
