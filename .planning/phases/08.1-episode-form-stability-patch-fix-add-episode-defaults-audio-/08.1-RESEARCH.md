## User Constraints (from CONTEXT.md)

### Locked Decisions

- **D-01:** When a previous episode exists, auto-fill the new episode publication date as seven calendar days after the latest episode’s date/time, preserving its local time and timezone representation.
- **D-02:** When no previous episode exists, default the publication date to the current date/time.
- **D-03:** “Latest episode” is determined from the existing episode publication-date ordering used by the Add Episode workflow.
- **D-04:** Extract and populate metadata only for the episode audio upload, not trailer audio.
- **D-05:** Populate Duration and Bytes only after upload completion, using values confirmed by the backend.
- **D-06:** Display duration as `HH:MM:SS`.
- **D-07:** Display bytes as decimal megabytes (`1 MB = 1,000,000 bytes`).
- **D-08:** If required duration or byte metadata cannot be extracted/confirmed, the upload must fail rather than leave a required field blank.
- **D-09:** Default participants are configured in frontend environment/configuration so an administrator can change the list without changing component logic.

- **D-12:** Duration, Bytes, and Spotify ID are not user-editable.
- **D-13:** Their read-only state is communicated through light-gray field styling only; no helper or hint text is required.

## Summary

The phase should stay a small cross-repository contract patch. The Angular editor already owns the relevant orchestration: `ManageComponent.loadEpisodes()` computes Add Episode defaults, `uploadMedia()` handles multipart progress and response mapping, `isEpisodeSaveDisabled()` controls Save, and `episode-form.component.html` renders the fields. [VERIFIED: codebase grep]

The largest missing capability is backend-confirmed episode-audio metadata. The sibling API’s upload route validates/stages MP3 bytes and starts transcription, but its response currently includes the staged filename and transcription fields, not duration or bytes; the database and DTO can store both values, but the upload path does not derive them. [VERIFIED: sibling API source] The planner should therefore coordinate a backend upload-response change with a thin Angular mapping change and tests; trailer-audio must continue through the same existing route without metadata behavior being added. [CITED: .planning/phases/08.1-episode-form-stability-patch-fix-add-episode-defaults-audio-/08.1-CONTEXT.md]

**Primary recommendation:** add server-side MP3 metadata extraction/validation to the sibling API’s `audio` upload path, return a response containing confirmed `duration` (`HH:MM:SS`) and `bytes`, map those fields only in the Angular `audio` branch after `HttpResponse`, and add focused Manage/API contract tests before the existing build gate. [VERIFIED: sibling API source] [CITED: docs/ARCHITECTURE.md]

## Architecture Patterns

### Existing Episode Upload Flow

```text
Episode form file input/drop
  -> ManageComponent.uploadMedia(editor, kind, file)
  -> ApiService.uploadEpisodeAudio(...) [multipart field: file, progress events]
  -> sibling API requireAuth + Multer validation/staging
  -> API-confirmed JSON response
  -> ManageComponent HttpResponse branch
       -> audio only: map duration/bytes + transcription status
       -> trailer: preserve existing filename-only behavior
  -> read-only form fields / success or bounded error
```

The current flow is verified by the Angular upload definitions/service and the sibling API’s `makeUploadRoute`; only the audio response contract and audio-specific response mapping need to expand. [VERIFIED: codebase grep] [VERIFIED: sibling API source]

### Publication Default Pattern

`loadEpisodes()` sets `suggestedNextPubDate`, then schedules `ensureAddEditorDefaults()`. `computeSuggestedNextPubDate()` currently selects the maximum parsed `pubDate`, adds seven via `Date.setDate()`, and converts to `datetime-local`; the empty list uses `new Date().toISOString()`. [VERIFIED: codebase grep] This already matches the requested algorithm at a high level, so planning should focus on initialization races, invalid dates, DST/calendar-day tests, and ensuring reset/new-editor flows reapply the refreshed suggestion rather than replacing the helper wholesale. [CITED: .planning/phases/08.1-episode-form-stability-patch-fix-add-episode-defaults-audio-/08.1-CONTEXT.md]

### Participant Configuration Pattern

The current participant cards come from a hard-coded `readonly memberOptions` array of `{name, character}` objects, while `selectedMembers` is editor state and `toggleMember()` synchronizes `formModel.authors`. [VERIFIED: codebase grep] The planned configuration should be a separate environment value containing names, then intersect that list with the actual member/catalog options before selecting defaults. Unknown names must be ignored; do not inject arbitrary configured values into `authors`. [CITED: .planning/phases/08.1-episode-form-stability-patch-fix-add-episode-defaults-audio-/08.1-CONTEXT.md]

### Music-Credit Validation Pattern

Music entries are structured objects with `name` and `links`; `serializeStructuredEntries()` currently retains an entry when either has content and serializes links after trimming. [VERIFIED: codebase grep] The required invariant should be evaluated against trimmed values before Save and should require at least one entry whose trimmed `name` is non-empty and whose trimmed reference URL is non-empty. The template should expose a concise validation state while `isEpisodeSaveDisabled()` remains the single Save gate. [CITED: .planning/phases/08.1-episode-form-stability-patch-fix-add-episode-defaults-audio-/08.1-CONTEXT.md]

### Read-Only Presentation Pattern

Duration and Bytes are already native `readonly` inputs; Spotify ID is currently a normal editable text input. [VERIFIED: codebase grep] Add a shared light-gray class or equivalent field styling and apply it to all three fields while retaining native `readonly` behavior. No helper/hint copy is required. [CITED: .planning/phases/08.1-episode-form-stability-patch-fix-add-episode-defaults-audio-/08.1-CONTEXT.md]

## Common Pitfalls

### Pitfall 1: Treating a staged upload as metadata-complete

**What goes wrong:** The current Angular branch marks any non-empty API response as staged and leaves `duration`/`bytes` untouched. [VERIFIED: codebase grep] **Why it happens:** The current API response contract contains filename/transcription data but no required audio metadata. [VERIFIED: sibling API source] **How to avoid:** Require numeric bytes and canonical duration in the audio response; clear/retain prior values deliberately on failure and surface the API error. **Warning signs:** success message with blank Duration/Bytes or values copied from `File.size`.

### Pitfall 2: Changing trailer-audio behavior accidentally

**What goes wrong:** Shared upload response mapping applies episode metadata rules to `kind === 'trailer'`. **How to avoid:** Gate metadata mapping/extraction explicitly on the audio upload kind and add a regression test for trailer response compatibility. [CITED: .planning/phases/08.1-episode-form-stability-patch-fix-add-episode-defaults-audio-/08.1-CONTEXT.md]

### Pitfall 3: Timezone/DST drift in publication defaults

**What goes wrong:** Converting through UTC strings or setting a fixed midnight changes the displayed local time. **How to avoid:** Test `computeSuggestedNextPubDate()` using a timestamp with a non-midnight clock and date-boundary/DST fixtures; preserve the existing local `Date` field conversion. [VERIFIED: codebase grep] [CITED: .planning/phases/08.1-episode-form-stability-patch-fix-add-episode-defaults-audio-/08.1-CONTEXT.md]

### Pitfall 4: Save gate validates only entry presence

**What goes wrong:** The default empty music entry serializes away, but a partially filled name/link entry can still be treated as present by a superficial check. [VERIFIED: codebase grep] **How to avoid:** validate trimmed name plus at least one trimmed non-empty link URL, and keep validation aligned with serialization. [CITED: .planning/phases/08.1-episode-form-stability-patch-fix-add-episode-defaults-audio-/08.1-CONTEXT.md]

### Pitfall 5: Configuration defaults overwrite user edits

**What goes wrong:** Reapplying defaults on every episode load/reset or catalog response can overwrite selections made by an operator. **How to avoid:** apply defaults only during new-editor initialization (and intentional reset), after the catalog/options are known, with an explicit guard for an active edit. [VERIFIED: codebase grep] [CITED: .planning/phases/08.1-episode-form-stability-patch-fix-add-episode-defaults-audio-/08.1-CONTEXT.md]

### Pitfall 6: Assuming the visible test suite protects ManageComponent

**What goes wrong:** The web repository has only the stale `src/app/app.component.spec.ts` visible test and no Manage/API upload tests. [VERIFIED: docs/TESTING.md] **How to avoid:** add focused unit/contract coverage for date defaults, audio response mapping/failure, participant filtering, music Save gating, and read-only template state before relying on `npm test`.

### Decimal MB display

```typescript
const decimalMegabytes = confirmedBytes / 1_000_000;
```

The presentation rule is resolved: keep the raw confirmed integer in the form model/API payload, divide by 1,000,000, round nonnegative values half-up to the nearest hundredth using integer arithmetic, and format exactly two decimal places. Thus 1,234,567 bytes displays `1.23 MB` and 1,235,000 bytes displays `1.24 MB`; adaptive precision is not permitted. [CITED: .planning/phases/08.1-episode-form-stability-patch-fix-add-episode-defaults-audio-/08.1-CONTEXT.md]

## Resolved Questions

1. **Draft audio-metadata persistence — RESOLVED against the API source.** The audio upload for an episode ID with no existing row stages the file under the existing episode media staging path and returns backend-confirmed `duration` and `bytes` in its draft-upload response; it does not create a separate audio reservation row. Angular retains those fields in editor state and sends them through `buildPayload` to `POST /episodes`. The API create path persists the fields in the episode row, promotes staged media, and returns the persisted episode DTO. If create fails, the API removes the partially created row and finalized media while retaining the staged source for retry; upload/probe failure removes the staged upload before success is reported. [VERIFIED: sibling API `makeUploadRoute`, `episodeRepository.create`, `promoteStagedMedia`, and create cleanup]

2. **Participant catalog authority — RESOLVED against the frontend/API source.** The current participant catalog is `ManageComponent.memberOptions`, the rendered author-card list. `GET /episodes/references` supplies guest/music suggestions and is not authoritative for participant defaults. Plan 02 keeps the catalog in the existing frontend component and intersects environment-configured names with that list before selecting authors; unknown names are ignored. [VERIFIED: ManageComponent and `episodes.routes.ts`]

3. **Decimal-MB display precision — RESOLVED in planning.** Use decimal MB (`bytes / 1,000,000`), round nonnegative values half-up to the nearest hundredth with integer arithmetic, and format exactly two decimal places. Keep raw confirmed bytes authoritative for payloads; tests cover 0, 1,000,000, 1,234,567, and 1,235,000 bytes. [CITED: 08.1-CONTEXT.md]
