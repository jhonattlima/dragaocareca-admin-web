# Milestone v1.0: Transcript Summary Integration

**Status:** ✅ SHIPPED 2026-07-29
**Phases:** 1-3
**Total Plans:** 6

## Overview

Integrated backend-generated episode summaries into the new-episode workflow. Operators can see transcript and summary progress, receive generated summary text automatically, edit it before saving, and see generation failures without losing access to the rest of the form.

## Phases

### Phase 1: Summary Contract Plumbing

**Goal**: Add the API/state hooks needed to represent AI summary generation for a new episode, reusing the existing transcript progress bar for summary progress once transcript reaches 100%.
**Depends on**: Nothing
**Plans**: 2 plans

Plans:

- [x] 01-01: Extend episode and transcription response handling for summary progress/value.
- [x] 01-02: Add manage-page state for summary generation without breaking existing transcript polling.

**Details:** The frontend API service and manage editor now represent the generated-summary endpoint, status, progress, timestamps, errors, and generated text.

### Phase 2: Auto-Fill Summary UI

**Goal**: Make the new episode tab show summary progress and auto-fill the generated summary into the form.
**Depends on**: Phase 1
**Plans**: 2 plans

Plans:

- [x] 02-01: Wire the summary progress UI into the existing episode form.
- [x] 02-02: Auto-fill the summary field from the backend response and preserve manual editing afterward.

**Details:** The existing audio-card progress bar switches from transcript to summary mode, and generated text fills the Summary textarea while protecting operator edits.

### Phase 3: Summary Resilience and Verification

**Goal**: Make the summary workflow safe under failure and verify that it does not disrupt the rest of episode creation.
**Depends on**: Phase 2
**Plans**: 2 plans

Plans:

- [x] 03-01: Add failure handling and reset behavior for summary generation.
- [x] 03-02: Verify the summary flow against the current manage screen behavior.

**Details:** Backend-reported and HTTP polling failures are visible, automated tests pass, the API typechecks, and the live API/browser flow was verified using a short clip derived from the available DC 338 MP3.

## Milestone Summary

**Key Decisions:**

- Keep summary generation in the backend; the Angular app only orchestrates polling and presents state.
- Reuse the existing transcript progress bar to preserve the sectioned operator workflow.
- Do not overwrite a summary manually edited by the operator.
- Await the backend transcript completion state before queueing summary generation.

**Issues Resolved:**

- Added generated-summary API contract and UI state.
- Fixed the backend transcript-done to summary-queue state-write race in API commit `3629492`.
- Surfaced unavailable summary polling errors in the frontend.

**Issues Deferred:**

- Add a dedicated API-level automated test for the transcript-to-summary transition.
- Address existing Angular bundle and metrics stylesheet budget warnings.
