## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User fixture → sibling API storage | External media enters a disposable API-side validation layout and must not overwrite the source fixture or unrelated media. |
| Browser origin → authenticated API | Manual validation crosses the production-like auth/CORS boundary and must prove bearer transport and header exposure. |
| API archive → downloaded file | ZIP entries and filename are release evidence for backend selector resolution and client delivery. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-06-05 | Tampering | DC 334 fixture provisioning | high | mitigate | Use a dedicated copy under the sibling API canonical layout, record pre-state, and restore all database/media/config changes in the validation artifact. |
| T-06-06 | Spoofing/Elevation | Browser auth/CORS delivery | high | mitigate | Validate authBypass pairing or real bearer auth, inspect the authenticated request, and treat missing Content-Disposition exposure as a release blocker. |
| T-06-07 | Information Disclosure | Release evidence and ZIP inspection | medium | mitigate | Keep fixture paths and tokens out of logs/evidence; record only selector, header, request-count, and archive-entry results. |
| T-06-08 | Denial of Service | Expired/failed/retry validation | medium | mitigate | Verify delivery retry does not create jobs, preparation retry is only for terminal preparation failure, and explicit reset is required for a new flow. |
| T-06-SC | Tampering | npm/pip/cargo installs | high | accept | No package install is planned; run package-diff checks and preserve the existing dependency set. |
