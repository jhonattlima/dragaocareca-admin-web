<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Angular HttpClient | The completed URL and server response cross into the client; bearer authentication must remain in the interceptor path. |
| HTTP response → DOM download anchor | Backend-controlled headers and Blob bytes become a browser filename and object URL. |
| Modal state → retry action | User retry must reuse the completed archive and must not create an unintended second preparation job. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-01 | Spoofing/Elevation | `ApiService.downloadEpisodeArtifact` | high | mitigate | Use injected HttpClient and existing AuthInterceptor; test the exact request seam and do not navigate directly to the API URL. |
| T-06-02 | Tampering | Content-Disposition filename parsing | high | mitigate | Accept only a validated server header filename, reject control/path separators and missing headers, and never derive a client filename per D-03. |
| T-06-03 | Information Disclosure/DoS | Blob object URL lifecycle | medium | mitigate | Scope one object URL to one delivery attempt and revoke it after click or thrown activation in guaranteed cleanup per D-04. |
| T-06-04 | Denial of Service | Automatic completion/retry state | high | mitigate | Guard by completed job identity, preserve terminal state, and make manual delivery retry call only the retained URL per D-02/D-05. |
| T-06-SC | Tampering | npm/pip/cargo installs | high | accept | No package-manager install task exists; the no-new-dependency constraint is enforced by the implementation and package diff check. |
</threat_model>
