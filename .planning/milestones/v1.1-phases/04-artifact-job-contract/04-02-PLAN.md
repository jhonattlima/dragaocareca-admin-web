<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Authenticated HTTP client -> Express routes | Episode IDs, JSON selectors, and opaque job IDs are untrusted. |
| Route -> job service/filesystem | Route parameters and persisted metadata must not become arbitrary path input. |
| API -> browser binary response | Headers and streamed bytes cross to a client that must not control filename or archive entries. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|----------|----------|-----------|----------|-------------|-----------------|
| T-04-02-01 | Tampering | POST selector validation | critical | mitigate | Validate the JSON array with Zod and the canonical selector parser; reject filenames, paths, internal kinds, empty arrays, unknown values, and malformed IDs before service calls. |
| T-04-02-02 | Elevation of Privilege | start/status/download routes | critical | mitigate | Apply requireAuth to each operation and assert unauthorized responses happen before episode lookup or archive access. |
| T-04-02-03 | Information Disclosure | opaque job lookup | high | mitigate | Query by both episode ID and job ID; return the same 404 for unknown and mismatched jobs without revealing ownership or paths. |
| T-04-02-04 | Collision/Tampering | archive filename and path | high | mitigate | Generate filename and job directory server-side from numeric episode ID and random job ID; reject persisted paths outside the job archive root before streaming. |
| T-04-02-05 | Denial of Service | start route | high | mitigate | Preflight before row creation, coalesce identical active jobs, cap request body through existing JSON middleware, and rely on worker TTL cleanup. |
| T-04-02-06 | Tampering | ZIP archive entries | high | mitigate | Use only catalog-derived archive entries rooted under the episode directory; never archive a client-named path. |
| T-04-02-SC | Tampering | npm/pip/cargo installs | high | accept | No package-manager install is planned; existing dependencies are reused. |
</threat_model>
