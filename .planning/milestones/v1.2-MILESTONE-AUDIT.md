# v1.2 Trailer Video YouTube Publishing — Milestone Audit

## Scope

This audit covers all six v1.2 phases: trailer upload (7), YouTube lifecycle (8), episode-form stability (8.1), title and hashtag authoring (9), operator workflow compatibility (10), and finalized trailer artifact downloads (11).

The milestone is substantially implemented and the main upload-to-publication and artifact-download paths are connected. The authored-hashtag reload gap found by the audit was fixed in commit `253e297`; the remaining items are verification debt in the sibling API repository and environment-limited browser checks.

### Previously identified gap — fixed

`ManageComponent.startEdit()` initializes the hashtag form value to an empty string. Persisted trailer hashtags are held in the YouTube job metadata snapshot rather than the Episode DTO, and that snapshot is not used to restore the field when an existing episode is reopened. Consequently, editing and saving an existing episode can send an empty hashtag list to `/commit`.

Affected behavior: `YOUTUBE-06` directly, with related preservation implications for `TITLE-01`, `TITLE-04`, and `OPS-02`/`OPS-05`.

Resolution: `ManageComponent` now restores persisted job metadata or same-session committed hashtags, and a regression test covers reopening an existing episode. The production build passes. The focused browser suite remains unavailable because ChromeHeadless cannot launch in this environment.

## Cross-phase integration

### Connected flows

1. Local MP4 selection, progress, cancellation, retry, and replacement.
2. New-episode draft reservation, staging, and promotion using the same draft identity.
3. Existing-episode replacement with rollback-safe preservation of the prior finalized file.
4. Private YouTube transfer, polling, retry, cancellation, reload recovery, and stale-response guards.
5. Summary/title/hashtag authoring followed by Save-time YouTube commit and publication.
6. Finalized `trailer-video` selection in the Episodes artifact modal.
7. Authenticated ZIP/native artifact download with server-side preflight and canonical `trailer.mp4` naming.

### Risky or incomplete links

- Existing-episode edit does not restore authored hashtags, so Save-time publication metadata can be incomplete after reload.
- UI artifact availability is initially inferred from the filename in the episode DTO; the API remains authoritative and rejects staged, missing, stale, or failed artifacts.
- The direct `/youtube-trailer-jobs/:jobId/publish` route has no Angular caller. This is intentional: the documented Save-time `/commit` path owns metadata application and publication.
- Frontend `authBypass` and API `AUTH_BYPASS` must remain aligned in local deployments.

### Verification-contract drift

Three older API verifiers fail because their expectations no longer match the current contracts:

- trailer staging expects no `youtubeJob`, although staging now intentionally starts private YouTube work;
- publication expects an obsolete draft behavior;
- trailer-artifact OpenAPI checking expects a literal size value that is not part of the current description.

These failures are not evidence of a new application-flow break, but they should be updated before release so automated verification reflects the approved v1.2 contract.

## Recommendation

The application-level audit gap is fixed. Before archiving v1.2, reconcile the three stale API verifiers in `dragaocareca-admin-api` and run the focused browser suites in an environment with ChromeHeadless. The current frontend build is green and the remaining items are verification/release-confidence work rather than an identified frontend integration defect.
